# Ansible для управления инфраструктурой

## 📜 Общее назначение

Этот каталог содержит роли и плейбуки Ansible для автоматизированной установки, настройки и управления инфраструктурой и сервисами проекта Active Bank. Он охватывает такие компоненты, как Kubernetes, мониторинг, логирование, CI/CD и другие вспомогательные сервисы.

---

## 🚀 Быстрый старт для новичка

Этот гайд предназначен для тех, кто настраивает рабочее окружение с нуля.

### 1. Клонирование репозитория
Сначала скопируйте проект на ваш локальный компьютер и перейдите в директорию `infra`.
```bash
git clone <URL_вашего_репозитория>
cd <путь_к_папке>/infra
```

### 2. Установка Ansible
Ansible рекомендуется устанавливать в виртуальное окружение Python, чтобы изолировать зависимости проекта.

```bash
# Убедитесь, что у вас установлен Python 3 и pip
python3 --version

# Создаем и активируем виртуальное окружение в корне проекта infra
python3 -m venv .venv
source .venv/bin/activate

# Устанавливаем Ansible
pip install ansible
```
> [!NOTE]
> После этого все последующие команды нужно выполнять в этой же сессии терминала с активированным окружением.

### 3. Установка зависимостей проекта
Теперь, когда Ansible установлен, перейдите в рабочую директорию и установите коллекции, необходимые для проекта.

```bash
cd infrastructure/ansible/
ansible-galaxy collection install -r requirements.yml
```
> [!IMPORTANT]
> Также убедитесь, что на вашей машине установлены клиенты `kubectl` и `helm`, так как многие роли используют их для взаимодействия с Kubernetes.

## ⚙️ Основные концепции и структура

### Структура директорий
- `artifacts/`: Директория с результатами работы Ansible (при необходимости).
- `inventories/`: Директория с файлами инвентаря для разных окружений (`dev`, `prod`).
- `playbooks/`: Плейбуки, которые описывают, какие роли и на каких хостах выполнять.
- `roles/`: Переиспользуемые роли для выполнения конкретных задач.
- `ansible.cfg`: Основной конфигурационный файл Ansible.
- `requirements.yml`: Список внешних коллекций Ansible, необходимых для работы.

### Инвентарь и переменные (Inventories & Variables)
Проект использует структурированный подход к управлению хостами и переменными для разных окружений.

- **`inventories/`**: Корневая папка для всех инвентарей.
    - **`inventories/dev/`**: Директория для `dev`-окружения.
    - **`inventories/prod/`**: Директория для `prod`-окружения.

Каждая директория окружения содержит:
- `hosts.yml`: Файл, в котором определяются хосты и их группировка (например, `master_nodes`, `worker_nodes`).
- `group_vars/`: Директория с переменными для групп хостов.

#### Как подгружаются переменные (`group_vars`)

Когда вы запускаете плейбук с указанием инвентаря (например, `-i inventories/dev`), Ansible автоматически ищет и загружает переменные из директории `inventories/dev/group_vars/` в следующем порядке:

1. **`group_vars/all.yml`**: Переменные из этого файла применяются ко **всем** хостам в инвентаре. Здесь находятся общие настройки.
2. **`group_vars/<group_name>.yml`** (или **`group_vars/<group_name>/main.yml`**): Переменные из файлов, названных в честь группы (например, `group_vars/kafka_nodes.yml`), применяются только к хостам, входящим в эту группу. Эти переменные имеют более высокий приоритет и **переопределяют** значения из `all.yml`.

### Плейбуки (Playbooks)
Плейбуки — это сценарии, которые запускают одну или несколько ролей на определенных группах хостов.

| Плейбук | Назначение | Целевые хосты |
|---|---|---|
| `install_kafka.yml` | Устанавливает и настраивает кластер Apache Kafka. | `kafka_nodes` |
| `install_kubernetes.yml` | Устанавливает и настраивает кластер Kubernetes. | `master_nodes`, `worker_nodes` |
| `test_connection.yml` | Проверяет SSH-соединение и собирает факты о хостах. | `all` |
| `uninstall_kafka.yml` | Полностью удаляет Kafka с целевых хостов. | `kafka_nodes` |
| ... | ... | ... |

### Роли (Roles)
Для стандартизации и лучшего понимания назначения ролей рекомендуется использовать следующие префиксы:

| prefix_ | description |
|---|---|
| `install_*` | Для первоначальной установки и базовой настройки компонентов. |
| `config_*` | Для детальной настройки уже установленного сервиса. |
| `manage_*` | Для операционных задач и управления жизненным циклом (старт, стоп, перезапуск). |
| `deploy_*` | Для развертывания приложений. |
| `test_*` | Для выполнения тестов и проверок. |
| `remove_*` / `uninstall_*` | Для полного удаления компонента. |

##  workflows (Рабочие процессы)

### Запуск плейбуков
**Важно:** Все команды `ansible-playbook` следует запускать из директории `infrastructure/ansible/`.

Ansible настроен на использование инвентаря на основе директорий. Это позволяет легко переключаться между окружениями (`dev`, `prod`) с помощью флага `-i`.

> [!EXAMPLE] Пример запуска плейбука для DEV окружения
>
> ```bash
> ansible-playbook -i inventories/dev playbooks/install_kubernetes.yml
> ```
>
> - `-i inventories/dev`: Указывает Ansible использовать инвентарь из директории `dev`, включая переменные из `inventories/dev/group_vars/`.

### Управление секретами (Ansible Vault)
Для хранения чувствительных данных (пароли, токены) в этом проекте используется **Ansible Vault**. 

- Не храните секреты в открытом виде.
- Для зашифровки/расшифровки файлов используйте команды `ansible-vault encrypt` и `ansible-vault decrypt`.
- При запуске плейбуков, использующих зашифрованные переменные, добавляйте флаг `--ask-vault-pass`.
